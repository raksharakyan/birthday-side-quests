# Decisions log

Owner: Orchestrator. Format: date · decision · reason · who won (if conflict).

1. **2026-10-02 · Stack: Vite + vanilla TypeScript + Leaflet.** Smallest bundle, minimal deps (supply-chain), no framework HTML-string templating → easier XSS audit. (User approved.)
2. **2026-10-02 · Hosting: GitHub Pages.** No extra accounts. Limitation: no custom HTTP headers → CSP + Referrer-Policy via `<meta>`; `X-Content-Type-Options`, `Permissions-Policy`, `frame-ancestors` cannot be set. A `_headers` file is shipped for anyone deploying to Cloudflare Pages.
3. **2026-10-02 · Offer facts come only from curated `offers.json`** researched from official brand pages. Unconfirmed → `verified:false` → "Check with store".
4. **2026-10-02 · Hybrid live search ("Found online").** Cloudflare Worker proxies a search API (Tavily free tier). Worker accepts only `{month, country}` (never free text), so user location never leaves the browser except to Nominatim/Overpass. Results are labelled unverified, rendered as plain text. Section hidden if `VITE_WORKER_URL` unset.
5. **2026-10-02 · No AI text generation in v1.** Cute quest lines from deterministic category templates. Zero keys, zero hallucination risk.
6. **2026-10-02 · Referrer conflict (Security vs. Nominatim policy).** Global `no-referrer`, but Nominatim/Overpass fetches use `referrerPolicy: 'strict-origin'` (origin only, no path/user data) so OSM can identify the app as its policy requires. Security approved: origin carries no user data.
7. **2026-10-02 · Online tab** for online/app-only birthday deals; city optional there, country selectable manually.
8. **2026-10-02 · Seed data accepted from research (25 offers: 16 verified, 9 "Check with store").** Orchestrator spot-checked Starbucks US T&C, The Body Shop India loyalty page and Krispy Kreme UK rewards page via WebFetch, and all matched the draft. Discount-only offers (Westside, Body Shop IN Platinum) kept because the user explicitly wants birthday discounts too. Rejected brands (Chaayos, Dunkin', H&M, Häagen-Dazs, Pret, etc.) listed in docs/OFFER_RESEARCH.md.
9. **2026-10-02 · OSM tiles also use `referrerPolicy: 'strict-origin'` (extends #6).** The OSM tile usage policy needs an identifying Referer. A tile request already reveals the map area, and the Referer adds only the site origin (no path or query, and the app never puts location in the URL). **Security approved.**
10. **2026-10-02 · Lighthouse CI runs in its own CI job.** `@lhci/cli` is fetched with `npx` and isn't locked, because its dependency tree carries high-severity advisories that would fail `npm audit`. The job has `contents: read` and no npm cache write, and it never touches the Pages artifact. `deploy` still needs it to pass. **Security won** over the simpler single-job setup.
11. **2026-10-02 · CSP keeps `img-src data:`.** Leaflet 1.9.4 assigns a 1×1 `data:image/gif` to tiles when it aborts loads during zoom or pan, and removing it produces CSP violations. A data: image can't run script. Everything else stays without `unsafe-*`.
12. **2026-10-02 · External text hygiene (`src/text.ts`).** Text from Nominatim, Overpass and the Worker has C0/C1 controls, bidi embeddings, overrides, isolates and marks, and invisible formatting characters stripped. `offers.json` entries containing them are rejected. ZWJ/ZWNJ are allowed because Kannada, Hindi and other Indic place names, and emoji sequences, need them. The Worker keeps the same character class. **Security.**
13. **2026-10-02 · Private vulnerability reporting enabled.** It is the only reporting channel listed in `SECURITY.md`. **Security.**
14. **2026-10-02 · QA-04 resolved by Orchestrator.** No offers are truly worldwide (`"*"`), so the Online tab's blank option is relabelled "Pick your country…" (still blank = worldwide-only filter) and the per-country empty state no longer points users to a dead end. No fake global offers were added.
15. **2026-10-02 · Overpass query reshaped after live failure (Orchestrator; Security: no new origins, CSP unchanged).** On the live site, Bengaluru's query `nwr["name"~…,i](around:5000)` timed out on overpass-api.de (>28s, 0 results). New shape narrows to food amenities + shops inside the circle first, then filters by wikidata/name/brand: ~6s, 38 branches in tests. One retry after 2s on 429/504 (server overload). Mirrors were evaluated and rejected (slow/unreachable, and they'd widen connect-src).
16. **2026-10-02 · Location autocomplete via Photon, not Nominatim (Full-Stack; Security to review).** Nominatim's usage policy forbids client-side autocomplete, so as-you-type suggestions come from Photon (`photon.komoot.io`, komoot's public OSM geocoder, CORS `*`). Photon gets **only the typed text** (debounced 300 ms, ≥3 chars, ≤120 chars, in-flight request aborted on each keystroke, in-memory cache, 5 s timeout) with `q/limit=5/lang=en/layer=city|district|locality`. No coordinates or bias params, `credentials: 'omit'`, `referrerPolicy: 'strict-origin'`. Picking a suggestion uses its coordinates and country directly and skips Nominatim. Free text plus Enter still goes to Nominatim. Photon failures mean silently no suggestions. CSP: `https://photon.komoot.io` was added to `connect-src` only. The public Photon API is "fair use", and extensive use is throttled.
17. **2026-10-02 · User-selectable search radius (Full-Stack).** A "Search radius" select offers 2, 5 (default), 10 and 20 km and is passed to `buildOverpassQuery` (still clamped to 100 m–20 km, same POI-first shape as #15). The branch cap is 60 for ≤5 km and 150 for 10–20 km (`out center N` and the parse cap match). Changing the radius re-runs the lookup for the place already shown, with no new geocoding. The Nearby tab keeps every country quest. Quests with a branch inside the circle come first, nearest first, with "x km away". The rest follow under "More quests in <Country> (no branch found within N km)". The map draws the circle and fits it.
18. **2026-10-02 · Session persistence in `sessionStorage` (Full-Stack; user chose session-only; Security to review).** A refresh used to wipe the search. One versioned key (`bsq-session`) now holds only `{v, city, lat, lng, countryCode, month, radius, tab, done}`. It is written only when the user searches or changes one of those, validated strictly on load (exact keys, ranges, ISO-2, radius allowlist, offer-id charset, no markup or control/bidi characters in the city; anything else is removed), and wiped by a **Clear search** button. Reload re-runs the search from the stored coordinates (Overpass only, no Nominatim). **Why session over localStorage:** the user asked for session-only; `sessionStorage` is per tab and is deleted when the tab closes, so a shared or public computer doesn't keep someone's city around, and there is nothing to expire or migrate. localStorage, cookies and IndexedDB stay banned, location still never goes in the URL, and only `src/session.ts` may touch storage (unit-tested). The UI note now reads "We don't store anything on our servers. Your search stays in this browser tab and clears when you close it."
19. **2026-10-02 · City-only location input, any city worldwide (Full-Stack; supersedes the layers in #16).** The input is "Your city" (placeholder "e.g. Bengaluru"). Photon autocomplete uses only `layer=city` (place=city/town/village plus city-level admin areas; tested live with "Beng", "Manch", "Pune", "Kyo"), and `parsePhoton` also drops any feature whose `type` isn't `city`. Free text goes to Nominatim with `featureType=city`. The search centre is the city centre and the radius picker stays. `osm_tag=place:*` filters were rejected because they dropped Manchester, UK (an admin boundary in Photon). Trade-off: NYC boroughs such as Brooklyn are `place=suburb` (Photon `district`), so autocomplete offers the US towns named Brooklyn instead; typing "Brooklyn" + Enter still resolves via Nominatim (`featureType=city` returns Brooklyn, Kings County, NY).
20. **2026-10-02 · Online tab lists every country (Full-Stack).** The country select has all 249 ISO 3166-1 alpha-2 codes (`src/countries.ts`), named with `Intl.DisplayNames(['en'], {type:'region'})` (no data download). Countries with their own online quests come first in an optgroup, with a count that includes worldwide `"*"` offers (e.g. "India (28)"); all others follow alphabetically. Worldwide offers are still included for any selection. Searching or picking a city auto-syncs the Online country and refreshes Online (and Found online when open); the Online tab label shows the count ("Online 28"). `el()` gained the plain-text `label` attribute for `<optgroup>`.
21. **2026-10-02 · "Soft Premium" redesign with the plum accent and variable fonts (UI/UX; user approved the prototype in `docs/design/` and picked plum).** Tokens: porcelain neutrals plus one accent, `--accent #6B2D5E`, `--accent-hover`/`--accent-ink #5A2450`, `--accent-active #4A1D42` (derived, white on it 13.59:1), `--accent-tint #F2E7F0`, `--accent-tint-2 #E6D2E2`; every text pair is AA (list in HANDOFFS "UI/UX: soft premium port"). Fonts: `@fontsource-variable/bricolage-grotesque` (display, "opsz" build: weight + optical size) and `@fontsource-variable/plus-jakarta-sans` (body, "wght" build), pinned to exact `5.3.0`, self-hosted, only the latin + latin-ext subsets declared in `src/styles/fonts.css` (latin-ext carries ₹), `font-display: swap`, no preload (Lighthouse perf stayed 0.99 without it). `@fontsource/fredoka` and `@fontsource/nunito` removed. All emoji removed from the UI in favour of inline SVG icons built with `createElementNS` (`src/render/icons.ts`). The segmented controls' selected thumb gets a 1px `--ink-3` edge (4.78:1 on the track) instead of the `--line-control` edge DESIGN.md suggested, because `--line-control` on `--sunken` is only 2.89:1. The city label stays "Your city" (DECISIONS #19) rather than the prototype's "City or area". The radius control is now a real radio group (2/5/10/20 km) styled as a segmented pill.
